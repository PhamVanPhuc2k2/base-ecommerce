## Task 1: Khởi tạo dự án

**Files:** `apps/web/*`

- [ ] **Bước 1: Khởi tạo**

```bash
cd apps
npx create-next-app@latest web --typescript --tailwind --app --no-src-dir \
  --import-alias "@/*" --no-eslint --use-npm
```

⚠️ **`apps/web/` đã tồn tại** và chứa `lib/api/generated/schema.ts` — file sinh
từ `openapi.yaml`, **không được mất**. Sao lưu trước, khôi phục sau khi khởi tạo,
rồi xác nhận `task openapi` sinh lại ra đúng file đó.

- [ ] **Bước 2: TypeScript strict thật**

`tsconfig.json` phải có, ngoài `strict: true`:

```json
"noUncheckedIndexedAccess": true,
"noImplicitOverride": true
```

`noUncheckedIndexedAccess` là cái đáng giá nhất: `arr[0]` thành `T | undefined`,
nên quên kiểm mảng rỗng là **lỗi biên dịch** thay vì `undefined` lúc chạy. Đây
đúng tinh thần dự án — dịch lỗi lúc chạy thành lỗi lúc build.

- [ ] **Bước 3: Biome thay ESLint + Prettier**

```bash
npm i -D --save-exact @biomejs/biome
npx biome init
```

Bật `formatter`, `linter`, và `organizeImports`. Thêm script:

```json
"lint": "biome check .",
"lint:fix": "biome check --write .",
"typecheck": "tsc --noEmit"
```

⚠️ Loại trừ `lib/api/generated/` khỏi Biome — file đó do máy sinh, format lại nó
sẽ làm `task openapi` báo lệch mỗi lần chạy.

- [ ] **Bước 4: `next.config.ts`**

```ts
const nextConfig: NextConfig = {
  // Cần cho Docker: gom đúng những gì runtime cần vào .next/standalone,
  // image từ ~1 GB xuống ~150 MB.
  output: 'standalone',
  // Ảnh sản phẩm hiện là URL ngoài. Danh sách host phải khai tường minh —
  // Next.js từ chối tối ưu ảnh từ host lạ, và đó là chủ ý: nếu không thì
  // server của mình thành proxy ảnh miễn phí cho cả internet.
  images: { remotePatterns: [{ protocol: 'https', hostname: '**' }] },
}
```

⚠️ `hostname: '**'` là **tạm cho P0.4** vì dữ liệu mẫu dùng URL bịa. Ghi comment
`TODO P1` để siết lại còn đúng CDN thật. Mở toang như vậy trên production là lỗ
hổng SSRF/lạm dụng băng thông.

- [ ] **Bước 5: Taskfile**

Thêm vào `Taskfile.yml` (gốc repo):

```yaml
  web-dev:
    desc: Chạy Next.js ở chế độ phát triển
    dir: apps/web
    cmd: npm run dev

  web-build:
    desc: Build Next.js production
    dir: apps/web
    cmd: npm run build

  web-check:
    desc: Biome + kiểm kiểu TypeScript
    dir: apps/web
    cmds:
      - npm run lint
      - npm run typecheck
```

**Kiểm chứng:**

```bash
task web-check     # phải xanh
task web-build     # phải xanh
task web-dev       # mở localhost:3000, thấy trang mặc định
git status         # node_modules KHÔNG được xuất hiện
```

⚠️ Kiểm `.gitignore` có `node_modules` và `.next`. Commit `node_modules` là sai
lầm khó gỡ.

## Task 2: Lớp `lib/`

**Files:** tạo `apps/web/lib/api/{server.ts,error.ts}`, `apps/web/lib/errors.ts`,
`apps/web/lib/format.ts`, `scripts/check-error-messages.sh`

- [ ] **Bước 1: `ApiError`**

```ts
export class ApiError extends Error {
  constructor(
    readonly code: string,
    readonly status: number,
    readonly requestId?: string,
  ) {
    super(`${code} (HTTP ${status})`)
    this.name = 'ApiError'
  }
}
```

- [ ] **Bước 2: `lib/api/server.ts`**

```ts
// Chỉ dùng trong Server Component. P0.4 KHÔNG gọi API từ trình duyệt, nên
// không cần NEXT_PUBLIC_API_URL — và nhờ vậy tránh được hẳn chuyện biến
// NEXT_PUBLIC_* bị nhúng vào bundle lúc build, khiến image staging và
// production khác nhau.
const API_URL = process.env.API_URL ?? 'http://localhost:8080/api/v1'

export async function apiGet<T>(path: string, opts?: { tags?: string[]; revalidate?: number }): Promise<T>
```

Xử lý lỗi: đọc body `application/problem+json`, lấy `code` và `request_id`, ném
`ApiError`. Body không phải JSON (ví dụ API chết, proxy trả HTML) thì vẫn phải
ném `ApiError` với code `UNKNOWN` — **không được** để `res.json()` ném lỗi parse
làm mất mã trạng thái thật.

⚠️ Phải xử lý cả trường hợp `fetch` **ném** (API không chạy, DNS hỏng): bọc lại
thành `ApiError('NETWORK_ERROR', 0)`. Đây chính là mục kiểm chứng số 9 — tắt API
Go rồi tải trang.

- [ ] **Bước 3: `lib/errors.ts` — bảng tra 27 mã**

```ts
export const errorMessages: Record<string, string> = {
  PRODUCT_NOT_FOUND: 'Không tìm thấy sản phẩm này.',
  ...
}

export function messageFor(code: string): string {
  return errorMessages[code] ?? 'Đã có lỗi xảy ra. Vui lòng thử lại.'
}
```

Lấy danh sách mã bằng:

```bash
(cd apps/api && go run ./cmd/checkcodes .)
```

Viết câu tiếng Việt **cho khách hàng đọc**, không phải cho lập trình viên: đừng
viết "DUPLICATE_SKU: vi phạm ràng buộc duy nhất", hãy viết "Mã sản phẩm này đã
tồn tại."

Thêm hai mã của riêng frontend: `UNKNOWN`, `NETWORK_ERROR`.

- [ ] **Bước 4: `scripts/check-error-messages.sh`**

Đối chiếu enum `code` trong `api/openapi.yaml` với khóa trong `lib/errors.ts`.
Theo đúng khuôn của `scripts/check-openapi-codes.sh`:

- Dùng **PyYAML** cho phía YAML (đừng grep).
- Phía TS: đừng grep thô. Cách bền nhất là chạy chính file đó — nhưng nó là
  TypeScript. Chọn một trong hai và **ghi lý do**: (a) regex trên các khóa
  `^\s*([A-Z_]+):` trong khối `errorMessages` và **báo lỗi nếu không trích được
  khối đó**, hoặc (b) thêm một script Node nhỏ dùng `tsx`/`node --experimental-strip-types`
  để import thật.
- Hai mã riêng của frontend (`UNKNOWN`, `NETWORK_ERROR`) phải được loại trừ
  tường minh, có tên trong script.

⚠️ **Phải chứng minh script bắt được vi phạm cả hai chiều** trước khi tin: xóa
một mã khỏi `errors.ts` → đỏ; thêm một khóa bịa → đỏ; và phá định dạng file để
regex không khớp → **cũng phải đỏ**, không được lặng lẽ báo OK.

Thêm vào `Taskfile.yml` thành `task error-messages` và vào `check`, và thêm job
vào `.github/workflows/ci.yml`.

- [ ] **Bước 5: `lib/format.ts`**

```ts
export function formatVND(amount: string): string
export function formatDate(iso: string): string
```

`formatVND` nhận **chuỗi**. Chuyển sang `Number` **bên trong hàm này** và viết
comment giải thích ranh giới: hiển thị thì được (trần `NUMERIC(15,2)` là ~10¹³,
còn `MAX_SAFE_INTEGER` ~9×10¹⁵), nhưng **cộng/nhân thì không** — P4 làm giỏ hàng
phải dùng thư viện decimal.

⚠️ Chuỗi không parse được phải trả về nguyên chuỗi, **không** trả `NaN ₫`.

**Kiểm chứng:** `task web-check`, `task error-messages` (xanh, rồi chứng minh đỏ
ba cách ở trên), và một trang tạm in ra `formatVND('25990000')`,
`formatVND('0')`, `formatVND('rác')`, `formatVND('9999999999999.99')`.

## Task 3: Layout và các trang trạng thái

**Files:** `apps/web/app/layout.tsx`, `error.tsx`, `loading.tsx`, `not-found.tsx`,
`apps/web/components/*`

- [ ] Header có logo + link danh mục, footer tối giản, breadcrumb dùng lại được.
- [ ] `app/error.tsx` (**phải là Client Component** — `'use client'`) hiển thị
      `messageFor(code)` và `request_id` nhỏ ở góc, kèm nút "Thử lại"
      (`reset()`).

⚠️ `error.tsx` **không bắt được lỗi trong layout của chính nó**. Muốn phủ cả
layout thì cần `global-error.tsx`. Thêm luôn, và ghi comment về khác biệt đó.

⚠️ Ở production, Next.js **giấu thông điệp lỗi thật** khỏi Client Component và
chỉ đưa `digest`. Nghĩa là `error.tsx` **không đọc được** `ApiError.code` trong
bản production nếu lỗi ném từ Server Component. Cách đúng: Server Component bắt
`ApiError` và render một component lỗi **của chính nó**, còn `error.tsx` chỉ là
lưới an toàn cuối. Ghi rõ điều này trong comment — đây là chỗ rất dễ tưởng đã
xong mà thật ra chỉ chạy đúng ở dev.

- [ ] `not-found.tsx` tiếng Việt, có link về trang danh mục.

**Kiểm chứng:** dựng một trang tạm ném `ApiError` để xem `error.tsx` thật sự
hiện. Kiểm ở **cả `npm run dev` và `npm run build && npm start`** — hai chế độ
này hành xử khác nhau, xem cảnh báo trên.

## Task 4: Trang danh mục

**Files:** `apps/web/app/danh-muc/page.tsx`, `components/product-card.tsx`,
`components/pagination.tsx`, `components/category-filter.tsx`

- [ ] **Bộ lọc trên URL**, đọc từ `searchParams` của Server Component. Không
      dùng `useState` — URL là nguồn sự thật, nhờ vậy chia sẻ link được và nút
      Back hoạt động đúng.

⚠️ Trong Next.js 15+, `searchParams` là một **Promise** và phải `await`. Đây là
thay đổi phá vỡ so với mọi ví dụ cũ trên mạng.

- [ ] Gọi `apiGet<ListProducts>('/products?' + qs)`. Tham số: `category`,
      `brand`, `sort`, `page`, `limit`, và `attr.<key>`.

⚠️ `attr.<key>` **không có trong type đã sinh** (object `query` đóng, không index
signature). Tự nối vào query string, và ghi comment tại chỗ.

- [ ] **Phân trang**: dùng `meta.has_next`/`has_prev`/`max_page`.

⚠️ **Đừng tự tính `page < total_pages`.** API có trần `max_page = 200`: ở trang
200 thì `total_pages` vẫn báo 8334 nhưng trang 201 trả **400 PAGE_TOO_DEEP**.
`meta.has_next` đã tính tới trần đó — cứ theo nó. Đây là mục kiểm chứng số 5.

- [ ] **Trạng thái rỗng**: không có sản phẩm nào khớp bộ lọc thì hiện thông điệp
      tử tế + nút xóa bộ lọc, không phải lưới trống.

**Kiểm chứng:** mục 3, 4, 5, 10 của đặc tả §8.

## Task 5: Trang chi tiết, sitemap, robots

**Files:** `apps/web/app/san-pham/[slug]/page.tsx`, `app/sitemap.ts`,
`app/robots.ts`, `lib/seo.ts`

- [ ] `generateMetadata` — `title`, `description`, `openGraph`,
      `alternates.canonical`.

⚠️ `generateMetadata` và `page` **cùng gọi API**. Đừng gọi hai lần: Next.js khử
trùng lặp `fetch` trong cùng một lần render, nhưng chỉ khi URL và tùy chọn
**giống hệt nhau**. Khác một chữ trong `next.tags` là hai request.

- [ ] JSON-LD `Product` qua `<script type="application/ld+json">`.

⚠️ `price` trong JSON-LD phải là **chuỗi số thuần** (`"25990000"`), không phải
chuỗi đã định dạng (`"25.990.000 ₫"`). Google từ chối dữ liệu có dấu phân cách.

- [ ] Slug không tồn tại → gọi `notFound()`, **không** để 500.
- [ ] `sitemap.ts`: chỉ sản phẩm `live`, ghi comment về trần 20.000 sản phẩm
      (`max_page 200 × limit 100`) và TODO P1 làm sitemap phân mảnh.
- [ ] `robots.ts`: chặn `/admin`.

**Kiểm chứng:** mục 6, 7, 8, 11 của đặc tả §8. Xem **HTML nguồn** (Ctrl+U) chứ
không phải DevTools Elements — JSON-LD phải có trong HTML server trả về, nếu nó
chỉ xuất hiện sau khi JS chạy thì Google có thể không thấy.
