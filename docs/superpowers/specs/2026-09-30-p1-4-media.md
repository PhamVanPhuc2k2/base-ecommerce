# P1.4 — Media: Thiết kế

> Thuộc P1, xem [tổng quan](2026-09-29-p1-tong-quan.md). Trả nợ P0.4:
> `remotePatterns: '**'` (lạm dụng băng thông/SSRF) và dữ liệu mẫu dùng ảnh bịa.

## 1. Phạm vi

**Có:** MinIO giữ ảnh gốc, imgproxy thu nhỏ + đổi định dạng; upload bằng
**presigned POST** thẳng từ client lên MinIO; bảng `media`; `Product.images`
chỉ nhận ảnh đã upload xong; storefront lấy ảnh qua loader riêng, bỏ
`remotePatterns`.

**Không:** dọn file mồ côi (upload dở không bao giờ hoàn tất); cắt/xoay ảnh;
video; CDN.

## 2. Luồng upload

```
admin ──POST /admin/media {content_type, size}──► API: tạo media 'pending',
      ◄── {id, key, upload: {url, fields}} ─────       ký POST policy (15 phút)
admin ──multipart POST (fields + file)──────────► MinIO: TỰ kiểm type, kích thước
admin ──POST /admin/media/{id}/complete────────► API: đọc 512 byte đầu, dò định
      ◄── media 'ready' ─────────────────────────       dạng thật → ready / xóa
admin ──PATCH /admin/products/{id} {images:[key]}► API: mọi key phải là media ready
```

### 2.1. Presigned POST, không phải presigned PUT

URL PUT ký sẵn **không giới hạn được kích thước** — ai cầm URL cũng đẩy được
file 5 GB vào bucket. POST policy mang điều kiện `content-length-range` và
`Content-Type`; MinIO tự từ chối file vi phạm, API không phải nhận byte nào.

### 2.2. Không tin Content-Type — dò 512 byte đầu

Client khai `image/png` rồi đẩy lên một file HTML thì policy vẫn qua (nó chỉ so
chuỗi khai báo). Bước `complete` đọc 512 byte đầu và dùng
`http.DetectContentType`: không phải JPEG/PNG/WebP thật → xóa object, trả 422
`INVALID_IMAGE`. Ảnh ra ngoài chỉ qua imgproxy (giải mã lại toàn bộ), nên một
file giả dạng không bao giờ tới trình duyệt nguyên văn.

### 2.3. Ký với endpoint CÔNG KHAI

API nói chuyện với MinIO qua `http://minio:9000` (mạng nội bộ), nhưng người
upload ở ngoài cần `http://localhost:9000`. Chữ ký S3 gồm cả host, nên policy
phải ký bằng một client cấu hình endpoint công khai — ký là phép tính thuần,
không gọi mạng, miễn đặt sẵn region (không thì SDK tự gọi hỏi region).

## 3. Phục vụ ảnh

### 3.1. imgproxy chỉ-preset, chỉ đọc bucket — không cần ký URL

Hai lớp đã đo được (xem TIEN-DO): `IMGPROXY_ONLY_PRESETS` → tham số tùy ý trả
404; `IMGPROXY_ALLOWED_SOURCES=s3://catalog/` → nguồn ngoài trả 404. Không ai
dùng imgproxy để tải ảnh internet hay đốt CPU bằng kích thước lạ. Ký URL
(HMAC) cần bí mật mà loader của next/image — chạy cả trong trình duyệt — không
được giữ.

### 3.2. Next.js proxy `/img/<preset>/<key>` — không `NEXT_PUBLIC_*`

Loader chạy trong trình duyệt nên không đọc được biến môi trường server. Nhúng
địa chỉ imgproxy bằng `NEXT_PUBLIC_*` là khóa nó vào bundle lúc build — đúng
cái bẫy P0.4 đã tránh cho `API_URL`. Loader trả đường dẫn TƯƠNG ĐỐI
`/img/w640/products/<id>.jpg`; Route Handler đọc `IMGPROXY_URL` lúc chạy và
chuyển tiếp (kèm header `Accept` để imgproxy chọn AVIF/WebP, trả `Vary:
Accept`). Route Handler chặn preset lạ và key sai định dạng trước khi gọi đi.

Production nên cho reverse proxy (Caddy) chuyển `/img/*` thẳng tới imgproxy để
bỏ một chặng qua Node — ghi ở thiết kế 05.

### 3.3. `Product.images` giữ KHÓA, không giữ URL

`products/0190….jpg` chứ không phải URL đầy đủ: đổi imgproxy, CDN hay tên miền
không phải sửa dữ liệu. Ghi sản phẩm với key chưa `ready` → 422
`VALIDATION_FAILED`, trường `images[i]`, mã `UNKNOWN_IMAGE`. Dữ liệu cũ (URL
bịa) chỉ bị kiểm ở lần ghi kế tiếp, cùng chính sách P1.3.

## 4. Schema

```sql
media (id, object_key UNIQUE, content_type, size_bytes, status pending|ready,
       created_at, updated_at)
```

## 5. Kiểm chứng

| # | Kiểm | Kỳ vọng |
|---|---|---|
| 1 | `task check`, `task web-check` | xanh |
| 2 | Upload JPEG/PNG/WebP qua đúng luồng | `ready`, key dạng `products/<uuidv7>.<đuôi>` |
| 3 | File vượt 10 MB / sai content-type so với policy | MinIO từ chối (403), không có object |
| 4 | Khai `image/png`, đẩy lên file HTML | `complete` → 422 `INVALID_IMAGE`, object bị xóa |
| 5 | `complete` khi chưa upload | 422 `UPLOAD_NOT_FOUND` |
| 6 | Policy hết hạn | MinIO từ chối |
| 7 | PATCH sản phẩm với key chưa ready / key bịa | 422, `images[i]` `UNKNOWN_IMAGE` |
| 8 | `/img/w640/<key>` | ảnh 640px, AVIF/WebP theo `Accept`, `Vary: Accept` |
| 9 | `/img/w999/…`, `/img/w640/../x`, key lạ | 404 ngay ở Next, không gọi imgproxy |
| 10 | Storefront: không còn request `/_next/image`, không còn 500 ảnh | Tab Network sạch |
| 11 | `remotePatterns` đã bỏ | `/_next/image?url=https://…` không còn proxy ảnh ngoài |
| 12 | Dữ liệu mẫu 33 sản phẩm dùng ảnh thật | trang danh sách, chi tiết, og:image hiện ảnh |
